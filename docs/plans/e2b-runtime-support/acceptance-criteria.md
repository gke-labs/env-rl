# E2B runtime support: acceptance criteria

Status: the design after the review of 2026-11-13, against `e2b` 2.63.0 and envd 0.10.2. The
statuses were checked on 2026-11-13 against `main` at `891160ac`, #363 at `d6a657dd`, #364 at
`e266fcbb`, #365 at `f4260135` and #384 at `885f8490`. `main` has none of the implementation, thus
no criterion is met. The plan is in [README.md](./README.md).

Status values: **met** (on `main`, with the tests named), **PR #n** (the head of that open pull
request meets it), **open** (not yet true on any branch; `(#n)` names the pull request that is
planned to carry it, `core` the core pull request for the wake hold), **folded** (a part of the
criterion named), **not planned** (decided against, with the reason in the row).

Ids are stable: `E2B-1` to `E2B-37`. An id is never renumbered or used again, and a retired id stays
in its table. The letter in a section title names the group and is not part of the id. "The program"
is a script that uses only the public E2B Python SDK and differs from its E2B version by the import
line.

test of #364 runs the released binary.

## Data plane, inherited from the SDK (D)

The data plane is the SDK's code on upstream's envd. One Kind test of the class (E2B-27) proves that
it works through our class; the criteria here are only what our code adds.

| ID     | Criterion                                                                                                                                                                                                                                                                                                                    | Status           |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| E2B-16 | The class sends the wake-hold header on each data-plane call: a command, a file call or a PTY call on a suspended environment waits for the wake and then succeeds (D-8a). That `commands.run` returns its result and raises on a nonzero exit and on a timeout is a part of E2B-27.                                         | PR #365, PR #384 |
| E2B-17 | `commands.run(background=True)`, `list`, `connect`, `kill`, `send_stdin` and the output callbacks work. The wake behaviour is E2B-16.                                                                                                                                                                                        | folded (E2B-27)  |
| E2B-18 | `envs` from `create` reach each command. The per-call `envs`, `cwd` and `user` are envd's own handling.                                                                                                                                                                                                                      | PR #365          |
| E2B-19 | A data-plane call on a deleted or crashed environment raises `SandboxNotRunningException`, as on E2B. Phase 1 does not translate the port proxy's `404` and `410` (D-8b); `integrations/e2b/README.md` documents the exception a program gets (#365). That the file calls work is a part of E2B-27. Not planned for phase 1. | not planned      |
| E2B-20 | `pty.create`, `send_stdin`, `resize` and `kill` work. The wake behaviour is E2B-16.                                                                                                                                                                                                                                          | folded (E2B-27)  |
| E2B-21 | envd rejects a call without a derived access token.
